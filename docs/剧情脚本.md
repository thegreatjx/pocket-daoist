# 《百宝小道修 (Pocket Daoist)》剧情脚本

> ⚠️ **未接入运行时（2026-11-26）**：本文与 `scripts/story.gd` 的 6 章文案目前没有被任何游戏代码调用，游戏内不播放这些剧情。现行状态见 [`PROJECT_STATE.md`](PROJECT_STATE.md)。

## 1. 主线

散修**沈砚**沿师妹**阿箬**留下的玉简追入大荒，一路见到妖兽愈发像人。
六章各给一条线索，终章揭开「大荒妖兽皆是被血月教以修士炼化的残魂」。

## 2. 标题界面

- 副标题：`循玉简入大荒 · 修仙割草肉鸽`（`Story.TITLE_SUBTITLE`）
- 开场引子（`Story.opening_lines()`）：

> 三月前，师妹阿箬留下一枚残缺玉简，只写了四个字：速离青冥林。
> 她没写理由。玉简背面却多了一道血痕，像被人仓促抹去。

## 3. 六章引子与结语

每章开头两行引子（打字机逐字浮现），章末首领击杀后一行结语横幅。

### 第一章　青冥林 · 薄暮（苍鬃狼王）
引子：
> 林雾压得极低，像一层没散干净的旧灰。
> 阿箬的玉简在这里第一次发烫，指向林心深处。

结语：
> 苍鬃狼王倒下时，玉简上的血痕却淡了一分。有人不想你看到她看见了什么。

### 第二章　赤砂荒原 · 血月（赤煞狼王）
引子：
> 赤砂上没有风，沙子却一直在动。
> 血月当空，沙下埋着的不是尸骨，是还没凉透的念想。

结语：
> 赤煞狼王散作一地黄沙。沙里露出半截白骨，指骨上刻着阿箬的名字。

### 第三章　幽冥鬼市 · 忘川（渡魂使者）
引子：
> 忘川两岸挂满灯笼，灯里燃的是记忆。
> 这里的鬼市专收失散修士的魂，价钱面议，货到付命。

结语：
> 渡魂使者沉入忘川。玉简亮起一行新字：别信带血的月亮。

### 第四章　白骨荒冢 · 九幽（白骨魔将）
引子：
> 九幽之下没有土，骨头就是地。
> 每一根肋骨都刻着功法，刻法与阿箬的师尊一模一样。

结语：
> 白骨魔将碎成齑粉。你在它的头盔里摸到一枚血月教的令牌。

### 第五章　玄冥祭坛 · 血祭（血祭妖帅）
引子：
> 祭坛上摆着七十二个空位，缺口正一盏盏亮起血光。
> 血月教在拿活人炼妖，今夜轮到第九批。

结语：
> 血祭妖帅散作黑雾。坛底露出阿箬的背影——她站在祭阵中央，没有回头。

### 第六章　大荒妖王巢 · 终章（啸月妖王 · 两阶段）
引子：
> 妖巢之下，全是人的脸。
> 玉简在掌心烧起来，最后一行字浮出：阿箬，别回头。

结语：
> 啸月妖王的两颗头都落了下来，大荒忽然安静了。

## 4. 结算

胜利（`Story.victory_text()`）：
> 血月教的祭坛塌了，那些被炼成妖的残魂一个个松开手，变回原来的名字。阿箬的名字排在第七十二位。你合上玉简：道途未竟，但她还在。

失败（`Story.defeat_text()`）：
> 道途未竟。你倒在雾里，玉简从怀里滑出去，那半枚玉简仍朝着阿箬的方向亮着。

## 5. 接入说明

### 5.1 数据入口

`scripts/chapters.gd`（`class_name ChapterData`）：

```gdscript
static func all() -> Array[Dictionary]      # 六章完整数据，按顺序
static func count() -> int
static func get_chapter(index: int) -> Dictionary
```

每章字典字段：

| 键 | 类型 | 说明 |
|---|---|---|
| `id` | int | 章号 1~6 |
| `name` | String | 章名，如「青冥林 · 薄暮」 |
| `subtitle` | String | 副标题，如「第一章」「终章」 |
| `duration` | float | 章长，恒为 90.0 秒 |
| `enemy_weights` | Dictionary | `{"wolf": 0.6, "ghost": 0.25, "skeleton": 0.15}`，三种小怪权重和为 1 |
| `elite_interval` | float | 精英刷新间隔（秒），45 → 28 递减 |
| `boss_name` | String | 章末首领名 |
| `boss_type` | String | 首领类型：`wolf` / `ghost` / `skeleton` |
| `palette` | Dictionary | `ground` / `fog` / `particle` / `tint`，四个 Color |
| `art_path` | String | 章节插画路径，如 `res://assets/art/chapter_1.png` |
| `intro` | Array[String] | 两行引子，来自 `Story.chapter_intro(id)` |
| `outro` | String | 章末结语，来自 `Story.chapter_outro(id)` |

### 5.2 剧情文本

`scripts/story.gd`（`class_name Story`）：

```gdscript
static func opening_lines() -> Array[String]      # 标题进游戏时播的开场引子
static func chapter_intro(chapter_id: int) -> Array[String]
static func chapter_outro(chapter_id: int) -> String
static func victory_text() -> String
static func defeat_text() -> String
```

常量：`TITLE_SUBTITLE`、`OPENING`、`CHAPTER_INTRO`、`CHAPTER_OUTRO`、`VICTORY_TEXT`、`DEFEAT_TEXT`、
`TITLE_ART_PATH`（`res://assets/art/title.png`）、`ENDING_ART_PATH`（`res://assets/art/ending.png`）。

### 5.3 章节推进

`scripts/stage_director.gd`（`extends Node`）：

信号：

```gdscript
signal chapter_started(chapter: Dictionary)
signal chapter_boss_spawned(chapter: Dictionary)
signal chapter_cleared(chapter: Dictionary)
signal run_finished(victory: bool)
```

公开方法：

```gdscript
func begin_run() -> void                    # 主控在开局时调用，开始计时与第一章
func notify_boss_killed(boss_name: String = "") -> void  # 主控在首领死亡时调用，弹出结语并进入下一章
func notify_player_failed() -> void          # 主控在玩家阵亡时调用，发 run_finished(false)
func current_chapter() -> Dictionary
func chapter_time() -> float
func chapter_time_remaining() -> float
```

`notify_boss_killed` 的 `boss_name` 可选。归属判定顺序：先用死亡的首领节点反查所属章节（刷怪器 `spawn_chapter_boss` 后会记下首领节点），其次按 `boss_name` 匹配，最后才退回按刷出顺序取最早那一个。
因此主控不传名字也不会错判章节；队列里没有对应首领时（主控自己的固定时间 Boss）直接忽略，不会误伤当前章节。
最后一章只有真把最终首领打死才会发 `run_finished(true)`；首领超时未死按未通关结束，不会误报胜利。

导出属性：

| 属性 | 默认 | 说明 |
|---|---|---|
| `auto_start` | false | 为 true 时 `_ready` 延后一帧自动开局；主控主动调 `begin_run()` 时保持 false |
| `boss_timeout` | 180.0 | 章末首领超时未击杀则强制结算该章，避免整局卡死；取值要大于首领实际战斗时长，否则会被误判成已击杀 |
| `advance_on_boss_kill` | true | true：首领被击杀后进入下一章（章节含首领战，同屏只会有一个首领）；false：章末刷出首领的同时立刻切下一章，章节严格按 `duration` 切分，旧首领可能残留在场上 |
| `chapter_transition_delay` | 4.2 | 首领死亡到下一章过场（或通关结算信号）之间的停顿秒数，用来盖过结语横幅的播放时长；设为 0 则立即推进 |

主控需要实现并被主控加进组的方法（全部 `has_method` 判空，缺了不会崩）：

| 节点 | 加入组 | 方法 |
|---|---|---|
| Spawner | `spawner` | `apply_chapter(chapter: Dictionary)`、`spawn_chapter_boss(chapter: Dictionary)` |
| Background | `background` | `apply_chapter(chapter: Dictionary)` |
| HUD | `ui`（现有 ui.tscn 已在该组） | `set_chapter(chapter: Dictionary)` |

首领归属的反查依赖刷怪器在 `spawn_chapter_boss` 之后保留首领节点（现有实现是私有变量 `_boss_instance`）；该字段取不到时自动退回按名字、再按刷出顺序匹配，不影响运行。

### 5.4 过场 UI

`scripts/chapter_banner.gd` + `scenes/chapter_banner.tscn`（CanvasLayer，layer = 20）：

```gdscript
func show_chapter(chapter: Dictionary, art: Texture2D) -> void  # art 传 null 走程序化渐变兜底
func show_outro(text: String) -> void                            # 章末结语横幅
func hide_all() -> void                                          # 主控重开局时收起
```

行为：淡入 0.45 秒 → 标题淡入 → 两行引子按字浮现（每字 0.06 秒，单行最长 1.1 秒）→ 停留至总计约 3.5 秒 → 淡出。
过场节点 `process_mode = PROCESS_MODE_ALWAYS`，主控在过场期间暂停游戏树也能播完。所有颜色取自 `chapter["palette"]`。
插画文件不存在时（`art_path` 指向的资源缺失）自动改用地面色 + 雾色的程序化渐变兜底，不报错。

### 5.5 主控接入步骤

1. `scenes/main.tscn` 里在 `Main` 下加一个 `StageDirector` 节点，`script` 指向 `res://scripts/stage_director.gd`。
2. 主控在开局（进入战斗场景）时调用 `stage_director.begin_run()`。
3. 主控在首领死亡时调用 `stage_director.notify_boss_killed()`；玩家阵亡时调用 `stage_director.notify_player_failed()`。
4. 主控监听 `run_finished(victory: bool)` 走结算；`victory == true` 时取 `Story.victory_text()`，失败取 `Story.defeat_text()`。通关信号会比最终首领死亡晚 `chapter_transition_delay` 秒发出，好让第六章结语横幅读完；不想要这段停顿就把该导出属性设为 0。
5. Spawner / Background / HUD 三处按 5.3 表格实现方法并加入对应组名，其余交给本模块。
